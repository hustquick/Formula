# OCR benchmark design — not yet a measured benchmark

本目录是Phase3设计框架：schema和样本计划。尚无完整数据集、可执行评分runner、人工校订会话或准确率报告。现有两张OCR fixture不能代表科研文档分布，不重复下载模型。

## 合法样本

以项目自建、原创公式和自写中英文段落生成干净图片、PDF及退化版本；可引入明确许可的公开数据，但必须逐项记录作者、来源、SPDX许可/授权、再分发与衍生条件。不能假定论文公开可下载就允许再分发。

至少覆盖28类：单变量简单式、分式、多层分式、根式、上下标、多重上下标、积分、多重积分、求和、连乘、极限、偏导、普通导数、矩阵、行列式、分段函数、希腊字母、数字/字母易混淆、物理公式、单位、化学公式、中文教材、英文论文、扫描PDF、低清、倾斜、噪声、小字号。

同一原创源的所有退化版本属于同一group，按group划分开发与冻结评估集，避免同一公式泄漏。记录dpi、字体、字号、倾斜角、噪声seed、压缩参数、crop坐标系和页大小；退化参数公开且可重现。样本数量与难度权重先小规模试测确定，不临时挑选最优样本报告。

`manifest.schema.json`定义未来记录；不把只有公式文本、没有合法图像或参考区域的条目算作可跑样本。原始输入immutable、gold独立复核，检测与识别分别评分；漏检/多检必须进入统计，不只对成功crop评分。

## 指标契约

| 指标 | 定义 / 限制 |
|---|---|
| exact_match | 原始OCR源码与gold字节一致；预先声明是否统一换行编码；不能事后清理结果提高分数 |
| normalized_match | 固定版本的语言感知归一化；只处理已声明的非语义差异，保护text、单位、大小写和宏；不是数学等价证明 |
| compile_success | 按language/backend/version编译，含失败、超时；单独记录语法成功，不能当正确性 |
| render_equivalence | 同字体/字号/引擎的参考与结果布局比较，冻结容差；不同引擎不可简单逐像素比较；人工复核歧义，视觉相似不证明语义相同 |
| manual_correction_count | 人类为达到正确公式执行的可见修改事务次数（一次输入连续段合并；撤销/重做单记），人工确认gold；与字符edit distance分开，不能用算法距离伪造人工数据 |
| processing_time | 从输入接受到完整结果的检测+识别墙钟时间；冷/热启动分开，记录硬件、模型版本、线程、缓存、超时与错误 |

还记录人工校订耗时、整页检测recall/precision与顺序、失败数。未执行的指标为null而不是0。报告分母包括失败和漏检；基本/专业模块在同一冻结集和硬件比较，给出分层结果和样本量，不仅总体均值。

## 运行与证据计划

未来runner适配现有 formula-ocr-runner.py，不复制推理实现。run manifest包含应用提交、runner hash、模型/权重指纹、Python依赖、设备、时间、样本manifest hash和参数。输出逐样本原始OCR/诊断/耗时，再离线评分；只读共享有效模型，不触发安装/修复。

人工校订通过真实Formula编辑器记录immutable原始OCR、最终FormulaDocument revision与操作日志；先验证计数器，再记录人工指标。发布前冻结gold和评分配置；有人工复核差异时留审阅记录，不静默修改gold。当前尚未执行以上benchmark。
